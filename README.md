# Native Commitlint-compatible commit guard

A Rust binary enforces the selected Commitlint conventional rules and a personal gh-only Git identity policy. Installed runtime dependencies are Git and gh, plus the operating system/Git's shell for hook entry points. Cargo/Rust, Bun, Python and JavaScript dependencies are development tools only.

The current policy is fixed: conventional type/scope/breaking-marker grammar, conventional type enum/case, subject empty/case/full-stop, trimmed header; printable ASCII with LF; at most 128 characters in the entire message including internal newlines, body and trailers, excluding terminal LF. Blank-line warnings do not become blockers. English is a writing requirement, not a grammar classifier. The selected lint rules are compared with 221 golden cases generated by Commitlint 21.2.3 with config-conventional and ignores disabled. Arbitrary JS configuration, plugins and full upstream rule coverage are outside the supported subset.

The independent guard checks both raw main identities against fresh `gh api --hostname github.com user` human authentication, permits recognized AI attribution, and checks every outgoing commit against the actual live push destination. It rejects signed/nonstandard commit objects. Hook chaining, message editor cleanup and linked worktrees are preserved. Installation activates strict mode explicitly; public devflow's default remains legacy.

```sh
cargo test --locked
cargo build --locked --release
./target/release/gh-commit-guard account
./target/release/gh-commit-guard message /path/to/message.txt
./target/release/gh-commit-guard install --home /tmp/isolated-home
```

Use an isolated HOME/GIT_CONFIG_GLOBAL/CODEX_HOME/CLAUDE_CONFIG_DIR for installation tests. Production setup changes user-level Git configuration and agent instructions; reopen shells afterward. `install --skills-only` installs native portable skills without global Git/shell activation. Containers use `install --container --repo <workspace>` and refuse host-mounted agent realpaths.

The PATH entry point guards ordinary no-verify and hooksPath overrides. Absolute/unwrapped Git, API writes, direct modification of the guard/configuration, and internal plumbing are beyond this local boundary. Native hooks block violations; automatic correction remains an agent workflow constrained to proven task-owned unpublished clean linear history, with backup refs and identical trees. No automatic force push. The pre-rebase gate checks source authors and credits, permitting malformed input wording to be reworded. Sequencer picks can retain invalid local messages; the agent must validate every resulting object, and pre-push remains the full outgoing-history backstop.

Do not replace an installed binary or policy while an active history-repair task binds its hash. Building and copying source bundles does not activate them on the host.

## Development oracle

`tests/fixtures/commitlint-golden.json` records upstream-derived inputs/results. Upstream Commitlint is never called by the shipped binary. Integration tests use isolated temporary repositories, real Git and fixture gh, with no Bun or Python on runtime PATH. Platform binaries are built from Cargo.lock; only actually built targets are distributed.

## Clone-free installation

For one-command release downloads and Homebrew installation, see [INSTALL.md](INSTALL.md). The bootstrap installs the existing native policy without a source checkout or compiler.

## Bundled targets and setup

`sh scripts/setup-commit-policy.sh` uses the supplied binary and installs the owner policy once per host. The standalone message command is `scripts/commitlint`; it accepts stdin, `--edit [FILE]` or `--from REF --to REF`. It never requires gh authentication. `scripts/check` provides the identity and push policy commands. `scripts/build.sh [target]` is development-only and requires Cargo/Rust plus an installed target toolchain.

| Target | Validation |
| --- | --- |
| aarch64-apple-darwin | Native Mac unit/integration tests |
| x86_64-apple-darwin | Cross-build only; this Mac has no Rosetta |
| aarch64-unknown-linux-musl | Linux ARM container unit/integration tests |
| x86_64-unknown-linux-musl | Linux x86 container unit/integration tests |

Linux binaries link musl statically. Windows binaries are not distributed; unsupported platforms fail closed. The Rust source separates platform-independent linting from Git hooks/setup so additional platforms can be built and verified separately. Binary manifests record file digests for distribution checks; they are not an immutable trust boundary against direct file modification.

The source skill and references live under `resources/`. The two consumer repositories carry self-contained skill/binary bundles. Templates can be copied independently, without fetching code or compiling at container startup. Changes here must be rebuilt, the resource/binary bundles synchronized, and their manifests rechecked before rollout. `tests/oracle/` is a development-only frozen Commitlint oracle; use Bun to regenerate the golden fixtures there if changing the supported lint rules. No oracle package appears in a runtime bundle.
